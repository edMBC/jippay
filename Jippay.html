Sección 01

El Reto y la Solución

Stack: Next.js 15 + TS + Zod Target de Despliegue: Vercel

El Problema de Confianza

Las empresas constituidas en EE. UU. con operaciones y contratistas en Latinoamérica procesan decenas de facturas mensuales por correo, PDF o chat. Aunque desean automatizar este flujo, temen ceder el control financiero a sistemas probabilísticos (cajas negras).

Hoy en día, el equipo de finanzas revisa manualmente cada cuenta, la compara con lo acordado y pide permisos por chat porque un LLM tradicional podría alucinar, ignorar un límite presupuestario o aprobar un pago indebido.

La Solución: Jippay (Agente Neuro-Simbólico)

Jippay resuelve el cuello de botella de la confianza separando estrictamente la lectura de documentos de la toma de decisiones financieras:

1. Cerebro Lector (IA)

Extracción Probabilística

Usa DeepSeek a través de Vercel AI SDK exclusivamente para leer textos desordenados (correos, PDFs) y estructurarlos en un JSON validado con Zod.

2. Auditor Contable (Código)

Decisión Determinista

Un motor lógico en TypeScript puro evalúa las reglas de la empresa sin alucinaciones y decide: PAGAR, ESCALAR o FRENAR.

"Usamos la IA para leer como un humano, pero usamos código estricto para auditar como un contador."

Sección 02

Arquitectura Full Stack (Opción B)

Construcción unificada en TypeScript pensada para compilación instantánea y despliegue directo en Vercel.

Frontend & Backend Core Next.js 15

  • Next.js 15 (App Router): Maneja tanto las 3 vistas de usuario como los Route Handlers (API serverless) en un mismo repositorio.
  • TypeScript Estricto: Tipado compartido de extremo a extremo entre el motor de reglas y la interfaz gráfica.
  • pnpm + Turbopack: Gestor de paquetes y empaquetador ultrarrápido para iterar en vivo durante el hackathon.

Validación y Contratos Zod

  • Zod (Reemplazo de Pydantic): Actúa como el guardián de tipos en el entorno TypeScript.
  • Structured Outputs: Obliga al LLM a responder estrictamente bajo el esquema InvoiceSchema. Si falta un dato o el tipo es incorrecto, falla de forma segura antes de llegar al motor de pagos.

Inteligencia Artificial DeepSeek + AI SDK

  • Vercel AI SDK: Integración limpia mediante generateObject conectada al modelo de DeepSeek o proveedor compatible.
  • Continue + DeepSeek Coder: Asistente integrado en VS Code para generar los componentes y pruebas a alta velocidad.

UI & Infraestructura Tailwind + Vercel

  • Tailwind CSS: Diseño sobrio en escala de grises y negro (estética institucional de alta confianza).
  • Vercel Edge / Serverless: Despliegue continuo con cada git push para que los jueces puedan probar la URL en vivo.

Sección 03

Estructura de la Interfaz (3 Vistas)

Flujo de navegación diseñado para demostrar el valor del producto a los jueces en menos de 3 minutos.

VISTA 01 / (Index) Landing Pitch

1. Landing Page (El Pitch de Confianza)

Puerta de entrada minimalista y oscura. Presenta la propuesta de valor directamente al jurado: "Automatiza tus cuentas por pagar sin perder el control."

Diagrama Interactivo: Muestra visualmente la separación entre "Lectura IA" y "Auditoría por Código".
CTAs Directos: Botones para ir a Configurar Reglas (/admin) o Auditar Facturas (/terminal).
VISTA 02 /admin Reglas de Empresa

2. Panel de Control (Administración de Reglas)

Pantalla donde el director financiero define las fronteras inflexibles del agente (CompanyRules). Todo cambio aquí afecta inmediatamente las decisiones en la terminal.

  • Límite por Pago Automático (USD): Input numérico / slider (ej. $1,000 USD). Encima de esto se escala a un humano.
  • Presupuesto Mensual Restante (USD): Indicador de saldo disponible para el periodo (ej. $5,000 USD).
  • Maestro de Proveedores Permitidos (Whitelist): Lista editable para añadir o bloquear empresas (ej. DevCorp, LatamDesign, CloudHost).
VISTA 03 /terminal Motor en Vivo

3. Terminal de Operaciones (Procesamiento y Auditoría)

El corazón demostrable del reto. Dividido en tres bloques claros para que cualquier persona entienda qué decidió el agente y por qué sin abrir el código:

A. Ingesta + Casos Trampa Área para pegar texto de facturas/correos + botones rápidos con facturas de prueba (Normal, Duplicada, Proveedor Nuevo, Exceso de Límite).
B. Inspector JSON (IA) Muestra en tiempo real los campos estructurados que DeepSeek extrajo del texto desordenado.
C. Log de Auditoría Tabla histórica con el estado (PAGAR, ESCALAR, FRENAR) y la explicación en lenguaje natural.

Sección 05

División de Responsabilidades y Zod

Reglas de negocio auditables y contratos de datos en TypeScript.

1. El Dominio Probabilístico (IA Extractora)

El LLM solo está autorizado para LEER y ESTRUCTURAR. Transforma un mensaje informal como "Hola equipo, adjunto cobro INV-204 de DevCorp por $650 USD por servidores AWS, vence el 2026-10-30" en: 

{
  "id": "INV-204",
  "emisor": "DevCorp",
  "monto": 650.0,
  "moneda": "USD",
  "fecha_vencimiento": "2026-10-30",
  "concepto": "Servidores AWS"
}

2. El Dominio Determinista (Motor de Reglas en Código)

El código puro evalúa en orden estricto las siguientes condiciones:

Regla 0: Factura Duplicada

Si invoice.id ya fue procesado previamente → Estado: FRENAR.

Regla 1: Proveedor Autorizado

Si emisor no está en proveedores_permitidos → Estado: FRENAR.

Regla 2: Presupuesto Disponible

Si monto > presupuesto_mensual_restante → Estado: FRENAR.

Regla 3: Límite Automático

Si monto > limite_monto_automatico → Estado: ESCALAR (Pide firma humana).

3. Esquemas Oficiales en Zod (src/lib/schemas.ts)

import { z } from 'zod';

export const InvoiceSchema = z.object({
  id: z.string().describe("Identificador único o número de la factura, ej. INV-001"),
  emisor: z.string().describe("Nombre de la empresa o contratista que emite el cobro"),
  monto: z.number().positive().describe("Monto total a pagar en valor numérico"),
  moneda: z.string().default("USD").describe("Código ISO de la moneda, ej. USD, COP, MXN"),
  fecha_vencimiento: z.string().describe("Fecha de vencimiento en formato YYYY-MM-DD"),
  concepto: z.string().describe("Descripción breve del servicio o producto cobrado")
});

export const CompanyRulesSchema = z.object({
  limite_monto_automatico: z.number().nonnegative(),
  presupuesto_mensual_restante: z.number().nonnegative(),
  proveedores_permitidos: z.array(z.string())
});

export const AgentDecisionSchema = z.object({
  invoice_id: z.string(),
  estado: z.enum(['PAGAR', 'ESCALAR', 'FRENAR']),
  razon: z.string(),
  timestamp: z.string()
});

export type Invoice = z.infer<typeof InvoiceSchema>;
export type CompanyRules = z.infer<typeof CompanyRulesSchema>;
export type AgentDecision = z.infer<typeof AgentDecisionSchema>;
Sección 06

Fronteras y Limitaciones del Sistema

Definición clara de qué entra y qué queda fuera del alcance del hackathon para mantener el foco.

NO

Cero movimiento de dinero real

El sistema no se conecta a pasarelas de pago reales ni a APIs bancarias. Su entregable final es la decisión auditada y explicada.

NO

Sin KYC ni verificación legal

No verifica la identidad jurídica de las empresas ni abre cuentas bancarias. Asume que la lista blanca fue aprobada por finanzas.

NO

Cero datos reales de clientes

Por restricciones del reto, todas las facturas, nombres de proveedores y reglas operan sobre un set 100% simulado.

NO

Sin juicio subjetivo de mercado

El agente jamás aprueba una factura fuera de las reglas por iniciativa propia. Cualquier excepción exige escalamiento humano.

Sección 07

Guía de Prompts (VS Code + Continue)

Cómo instruir a DeepSeek Coder en tu barra lateral derecha para generar el código de Next.js + TypeScript sin errores.

1. Inyección con @Files

Escribe @schemas.ts en el chat de Continue antes de pedir nueva lógica para que DeepSeek respete exactamente tus tipos Zod.

2. Edición Inline (Ctrl+I)

Selecciona una función o componente en el editor, presiona Ctrl+I y pide ajustes puntuales sin regenerar todo el archivo.

3. Salida JSON Estricta

Exige siempre al LLM extractor que responda únicamente bajo el esquema Zod sin texto conversacional alrededor.

Prompt 1: Crear Esquemas Zod (src/lib/schemas.ts)

Genera el contenido para el archivo `src/lib/schemas.ts` usando Zod en TypeScript para el proyecto Jippay. Necesito:
1. `InvoiceSchema`: id (string), emisor (string), monto (number), moneda (string), fecha_vencimiento (string), concepto (string).
2. `CompanyRulesSchema`: limite_monto_automatico (number), presupuesto_mensual_restante (number), proveedores_permitidos (array de strings).
3. `AgentDecisionSchema`: invoice_id (string), estado (enum: 'PAGAR', 'ESCALAR', 'FRENAR'), razon (string), timestamp (string).
Exporta también los tipos inferidos de TypeScript (`Invoice`, `CompanyRules`, `AgentDecision`).

Prompt 2: Crear Motor Determinista (src/lib/engine.ts)

@schemas.ts Crea el archivo `src/lib/engine.ts` con una función pura y determinista llamada `evaluateInvoice(invoice: Invoice, rules: CompanyRules, processedIds: string[]): AgentDecision`.
Reglas en orden estricto:
1. Si `invoice.id` está en `processedIds` -> retorna estado 'FRENAR' con razón explicando cobro duplicado.
2. Si `invoice.emisor` no está en `rules.proveedores_permitidos` (comparación case-insensitive) -> retorna 'FRENAR' indicando proveedor no autorizado en lista blanca.
3. Si `invoice.monto > rules.presupuesto_mensual_restante` -> retorna 'FRENAR' detallando presupuesto insuficiente.
4. Si `invoice.monto > rules.limite_monto_automatico` -> retorna 'ESCALAR' explicando que supera el límite automático y requiere aprobación humana.
5. Si cumple todo -> retorna 'PAGAR' explicando que cumple todas las reglas de la empresa.

Prompt 3: Set de Facturas y Casos Trampa (src/lib/mock-data.ts)

@schemas.ts Crea `src/lib/mock-data.ts` con una configuración inicial `defaultCompanyRules` (límite automático: 1000, presupuesto mensual: 5000, proveedores: ['DevCorp', 'LatamDesign', 'CloudHost']) y un array `sampleRawInvoices` con 5 textos realistas de correos/facturas que cubran:
1. Factura normal aprobable ($450 de DevCorp).
2. Proveedor desconocido no autorizado ($300 de HackerLabs).
3. Monto que requiere escalamiento humano ($1850 de LatamDesign).
4. Monto que excede el presupuesto restante ($6200 de CloudHost).
5. Cobro duplicado (mismo ID que la primera factura).
